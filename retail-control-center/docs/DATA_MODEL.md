# Data model — Google Sheets template

One spreadsheet, seven tabs. Row 1 holds the headers; **columns are matched by header name**, so the
order can be changed and extra columns (e.g. your own comments) are preserved by the app. Missing columns
the app needs are appended automatically on the first write.

Type legend: `text` · `date` (ISO `YYYY-MM-DD`, typed dates/serials are also accepted) · `timestamp`
(ISO UTC, written by the app) · `number` · `bool` (`TRUE/FALSE`, also `Yes/No`, `x`, `1/0`).

Fields marked **ext** are extensions to the original specification; they are optional in a hand-made
sheet (blank = default) but are always written by the app.

## STORES — one row per opening (store or new company)

| Field | Type | Notes |
|---|---|---|
| Store_ID | text | **Unique, immutable.** 2–8 letters/digits, used as Task ID prefix (`AMS`, `CZC`). |
| Store_Name | text | Display name, e.g. `Amsterdam Airport`. |
| Country / City | text | |
| Store_Type | text | `Standard Store` · `Airport Store` · `Company Opening` (airport stores get the ✈ mark). |
| Opening_Date | date | Blank = not known. |
| Opening_Date_Status | text | `Confirmed` · `Tentative` · `TBD` (drives the timeline milestone style). |
| Program_Type | text | `New Company` · `New Store`. |
| Overall_Status | text | Manual: `Planning`, `In Progress`, `On Hold`, `Opened`, `Cancelled` (`Opened` counts as a completed opening). |
| Overall_Progress | number | **Derived** — written back by the app as a convenience copy for Sheet readers; the app always recomputes it. |
| Risk_Level | text | `Low` · `Medium` · `High` — manual PM assessment. |
| Project_Manager | text | Owner name. |
| Last_Update | timestamp | Written by the app. |
| Version | number | Incremented by the app on each change (optimistic concurrency). |

## TASKS — one row per activity

| Field | Type | Notes |
|---|---|---|
| Task_ID | text | **Unique, immutable.** `{Store_ID}-{Area_ID}-{nnn}`, generated by the app (e.g. `AMS-HR-008`). |
| Store_ID | text | → STORES.Store_ID |
| Area | text | → AREAS.Area_ID (code, not name — areas can be renamed safely). |
| Task_Title / Description | text | |
| Start_Date / Due_Date | date | |
| Owner / Secondary_Owner | text | → OWNERS.Name |
| Status | text | One of the configured statuses (default: Not Started, In Progress, On Hold, Blocked, Completed, N/A). |
| Progress_Percentage | number | 0–100 (`68`, `68%` and `0.68` are accepted). Completed ⇒ 100. |
| Risk_Level / Priority | text | `Low` · `Medium` · `High`. |
| Task_Weight | number | > 0, default 1 — used only by the *weighted* progress method. |
| Dependency | text | Task IDs, comma separated. |
| Blocker | text | Free text; **non-empty ⇒ blocker** (so the description of the blocker lives in the cell). `TRUE` also works. |
| Decision_Required | text | Free text; **non-empty ⇒ decision required** (describe the decision). `TRUE` also works. |
| Last_Update / Last_Updated_By | timestamp / text | Written by the app. |
| Version | number | Incremented on each change. |
| Created_At **ext** | timestamp | Used to detect tasks created since the previous SAL. |
| Completed_Date **ext** | date | Set when status becomes Completed — keeps “completed late” measurable. |
| Archived **ext** | bool | Safe delete: archived tasks disappear from views and progress but keep their row and history. |

Derived, never stored: **Delay** (`today − Due_Date` for open overdue tasks), days to opening, area/store
completion, overdue / blocked / due-soon / decision counts.

## TASK_HISTORY — append-only audit trail

| Field | Type | Notes |
|---|---|---|
| History_ID | text | Unique. |
| Task_ID | text | Empty for opening-level (store) changes. |
| Store_ID | text | |
| Timestamp | timestamp | |
| Field_Changed | text | Field name (`Status`, `Progress_Percentage`, `Due_Date`, `Owner`, `Risk_Level`, `Priority`, `Blocker`, `Decision_Required`, `Description`, …), `Note`, `Created`, `Archived`, or `Store.<field>` for store changes. |

## AREAS

| Field | Type | Notes |
|---|---|---|
| Area_ID | text | Short code, **immutable**, used in Task IDs (`HR`, `LOG`, `SAP`). |
| Area_Name | text | Display name — rename freely. |
| Group | text | Optional parent used to nest areas in the minutes (SAP, ERP, POS… → `IT`). |
| Order | number | Configured order (SAL, minutes, matrix). |
| Active | bool | Disabled areas are hidden from dropdowns; their tasks stay. |

## Validation

On every read the app validates unique IDs, store/area/owner references, dates, progress range, statuses,
risk levels and weights. Nothing crashes on blank or malformed cells: safe defaults are applied and the
problems are listed in **Settings › Data quality** (with sheet, row key and field).
